# Security and sensitive-location reporting

This repository has two kinds of sensitive reports: software vulnerabilities
and archaeological location disclosures.

## Software vulnerabilities

Use the repository’s private **Report a vulnerability** flow when it is
available. Include the affected version, impact, reproduction steps, and the
smallest safe proof needed to verify the issue. Do not open a public issue
before the maintainers have had a reasonable opportunity to investigate.

Never include passwords, API keys, session cookies, signed download URLs,
private archive credentials, or personal data in a report.

## Possible new or vulnerable archaeological places

Do not use a public GitHub issue to disclose:

- exact or recoverable coordinates;
- parcel, route, access, or landowner details;
- high-resolution crops that reveal the location;
- unpublished findspots or museum security information;
- possible burials, sacred places, or community-restricted knowledge.

Preserve the original evidence and its provenance privately. Contact the
competent heritage authority, archaeological service, land manager, or
appropriate community body for the jurisdiction. Share only the minimum
location precision and evidence needed for that authority to assess the report.

You may open a public issue about the software behavior after removing the
location, source filename, imagery, metadata, hashes that identify private
material, and any other reversible locator.

## Scope

Good-faith research and reporting are welcome. This policy does not authorize
access to systems, accounts, land, collections, protected sites, or data that
you do not already have permission to use.
